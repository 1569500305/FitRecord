# 轻体记 V1 安装说明

## 一、安装包
- 交付 APK：仓库根目录 `fitrecord-v1.0.apk`（约 7.7 MB）
- 构建产物原件：`android/app/build/outputs/apk/release/app-release.apk`
- 包名 `com.fitrecord.app`，`versionName=1.0 (versionCode=1)`，`minSdk 26`（Android 8.0+），`targetSdk 35`
- 签名者 `CN=FitRecord`（**正式发布密钥**，非 debug key）

## 二、装到手机
方式 A（USB + adb，推荐开发自测）：
```powershell
# 需 adb 在 PATH（本机 platform-tools 见 env.ps1）
adb install -r "D:\桌面（2）\FitRecord\fitrecord-v1.0.apk"
```
方式 B（手动拷贝）：把 APK 传到手机，用文件管理器点击安装。
首次安装会提示「允许来自未知来源的应用」——这是侧载非商店应用的系统通用提示，确认后继续。

## 三、⚠️ 升级/覆盖安装的签名一致性（务必读）
- 覆盖安装要求**新旧包签名相同**。本 APK 用 `android/fitrecord-release.keystore` 签名。
- 该密钥库与 `android/keystore.properties` **必须妥善备份**：一旦丢失，将来无法用新签名覆盖旧包，用户只能卸载重装（会丢本机数据，除非先导出备份）。
- 因此 `keystore.properties` 与 `*.keystore` 已在 `.gitignore` 中，**不入库**；请另存到安全的离线位置。
- 若之前装的是 debug 签名的旧包，与本 release 包签名不同，**不能覆盖安装**，需先卸载（卸载前请在 App 内「数据备份与恢复 → 导出 JSON」保存数据）。

## 四、首次使用（核心打卡闭环）
1. 打开 App → 「我的」→「完善身体参数」→ 填**体重**（必填，用于算卡路里）。
2. 回「日历」→ 点某天 → 右下角 **+** 添加训练：选运动方式、时长、锻炼部位、备注 → 保存。
3. 自动算出卡路里与「相当于吃了多少」食物等价；日历格出现该类型的彩色点。
4. 「统计」页查看周/月五张图表；「我的 → 外观与主题」可切深色模式、周起始日。

## 五、卸载重装后用 JSON 恢复数据
1. 卸载前：「我的 → 数据备份与恢复 → 导出 JSON 完整备份」，把生成的 `fitrecord-YYYYMMDD-HHmm.json` 保存到手机Download目录或电脑。
2. 重装 App 后：「我的 → 数据备份与恢复 → 选择文件导入」→ 选该 JSON。
3. 先看「导入预览」的新增/跳过/覆盖计数，冲突策略默认「跳过已存在」（幂等，重复导不会翻倍）；需要以备份覆盖本机时再选「覆盖同名记录」。
4. CSV 只含训练记录表（不含身体参数/自定义类型），适合导入表格软件查看；恢复完整数据请用 JSON。
5. 若 App 提示「数据库无法打开」（文件损坏）：恢复页点「重建后从备份导入」→ App 会重建空库并自动跳到备份页 → 再选文件导入。

## 六、隐私
- 全程**无网络权限**，不联网、无广告、无账号；所有数据只存本机。
- 备份文件由用户自行保管，导出/导入都通过系统文件选择器（SAF）在用户可见位置完成，App 不上传任何内容。

## 七、构建复现（开发者）
```powershell
cd D:\fitrecord\android          # ASCII 联接路径（勿从中文路径直接构建，见 env.ps1 / 台账 P14/P18）
. .\env.ps1                      # 注入 JDK17、GRADLE_USER_HOME、目录联接
.\gradlew.bat :app:testDebugUnitTest :app:assembleRelease
```
构建前需 `android/keystore.properties` 指向存在的密钥库，否则 release 回退 debug 签名（只能自测，不能覆盖升级）。
