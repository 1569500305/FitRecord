| 项目 | 决策 |

## 三、选型理由与需求差异说明

### 3.1 为什么不用 React Native（需求文档第三节写"偏向 React Native"）

1. **与"使用 Android Room"直接冲突**：Room 是 Kotlin/Java 注解处理器库，RN 侧无法调用；若坚持 RN，必须换成 `expo-sqlite` / `WatermelonDB`，需求文档的"Room + Migration"条款就要整体改写。
2. **本机链路更短**：RN 需要 `npx @react-native-community/cli init`（下载模板）+ Metro + ADB/SDK + 常见原生库（Reanimated/Skia）还要 **NDK**，而本机没有 NDK，`react-native-reanimated` 一类会直接卡在 C++ 编译。
3. **交付目标只是 APK**：无跨端复用需求（纯 Android 单机 App），RN 的收益为零，成本与风险为正。
4. **性能与体积**：日历热力图 + 5 类图表重绘，Compose Canvas 自绘比 JS 桥更稳；原生 APK 无需打包 Hermes/JS bundle。
5. Node 已安装这一点并不构成选择 RN 的理由——它对本方案不是必要条件。

> 结论：需求文档"三、技术选型"中的"前端偏向使用 React Native"按本次确认结果**修订为原生 Kotlin + Compose**，其余功能需求不变。

### 3.2 其他已确认的偏差

| 需求原文 | 本次决策 | 原因 |
|---|---|---|
| "所有数据加密存储于本地 SQLite" | **不加密**，Room + 应用私有目录（`/data/data/<pkg>/databases`，其他应用不可读） | 加密需 SQLCipher，依赖 NDK/预编译 so + Keystore 口令管理，收益低（数据本就纯本地、不外传）；后续可平滑升级 |
| 模块2-3 "图片批量保存 / 生成长图报告" | **延后到 V1.1** | 你未勾选纳入首版；这是模块 2 中唯一被裁剪的项 |
| 模块5 "桌面小组件（Widget）" | **延后到 V1.1** | 需 Glance + 广播/刷新链路，工作量中等 |
| 模块5 "运动目标设定 + 进度环" | **延后到 V1.1** | 你未勾选 |
| 模块5 "深色模式" | **纳入 V1** | Material3 天然支持，成本低 |
| 模块5 "完全免费、无广告、无内购、无账号" | **纳入 V1 硬约束** | 参考截图中的广告位、"群打卡/微信用户"等社交元素**一律不实现** |

## 四、技术栈明细

| 层次 | 选型 | 版本 | 说明 |
|---|---|---|---|
| 语言 | Kotlin | 2.0.21 | JVM target 17 |
| UI | Jetpack Compose + Material 3 | BOM 2024.12.01 / material3 1.3.1 | 参考截图为圆角卡片 + 底部三 Tab 风格，Material3 可完全覆盖 |
| 编译器 | `org.jetbrains.kotlin.plugin.compose` | 2.0.21 | Kotlin 2.x 起 Compose 编译器随 Kotlin 版本，不再需要独立 composeOptions |
| 导航 | Navigation-Compose | 2.8.4 | 单 Activity；训练/日历/我的 三 Tab + 记录详情、统计、设置子路由 |
| 架构 | MVVM + Repository + UDF(StateFlow) | — | ViewModel + `collectAsStateWithLifecycle` |
| DI | 手写 `AppContainer`（Application 级容器） | — | 避免 Hilt/KAPT 额外插件与构建风险 |
| 数据库 | Room（KSP 注解处理） | 2.6.1 | KSP `2.0.21-1.0.28`；`exportSchema = true`，schema JSON 入库；只写 Migration，**禁用 `fallbackToDestructiveMigration`** |
| 键值配置 | DataStore Preferences | 1.1.1 | 身高/体重/年龄/性别、主题模式、周起始日 |
| 并发 | kotlinx-coroutines + Flow | 1.9.0 | Room 查询直接返回 Flow，日历/统计自动响应式刷新 |
| 序列化 | kotlinx-serialization-json | 1.7.3 | 备份导出/导入 JSON |
| CSV | 手写 `CsvWriter/CsvReader`（含 RFC4180 转义 + UTF-8 BOM） | — | 不引第三方库；BOM 保证 Excel 打开中文不乱码 |
| 文件读写 | SAF（`ACTION_CREATE_DOCUMENT` / `ACTION_OPEN_DOCUMENT`）+ 分享 Intent | — | **不需要 `WRITE_EXTERNAL_STORAGE` 权限**，Android 8~15 全兼容 |
| 日期时间 | `java.time`（LocalDate / YearMonth / Duration） | 内置 | minSdk 26 原生支持，无需 coreLibraryDesugaring |
| 图表 | Compose `Canvas` + `drawLine/drawArc/drawPath` 自绘 | — | 折线（时长趋势）、柱状（频率分布）、饼/环（运动方式占比）、雷达（部位训练占比）、日历热力（运动密度） |
| 主题 | Material3 `DynamicColors` 关闭，固定品牌色（绿 #2E9E5B / 橙 #F5A623 参考截图） | — | 浅色/深色/跟随系统 三态 |

| 混淆 | R8 **V1 关闭**（`isMinifyEnabled = false`） | — | 避免 Room/serialization 反射规则遗漏导致运行时崩溃；V1.1 再开启并补 rules |

### 4.1 数据模型（Room）草案

```
ExerciseType   (id, name, met: Double, color: Int, isBuiltin, sortOrder)      -- 内置库 + 用户自定义
BodyPart       (id, name, sortOrder)                                          -- 胸/背/腿/肩/手臂/核心/全身有氧/臀
TrainingRecord (id, date: LocalDate, startTime, durationMin: Int,
                exerciseTypeId, note, calories: Double, createdAt, updatedAt)  -- 一次"运动段"
RecordBodyPart (recordId, bodyPartId)                                          -- 多对多（锻炼部位多选）
UserProfile    (id, weightKg, heightCm, age, gender, weeklyGoal, createdAt)    -- 卡路里计算基准
FoodItem       (id, name, emoji, unitName, kcalPerUnit)                         -- 食物等价换算库
```

- **"健身次数"不落字段**，由 `SELECT COUNT(*) FROM TrainingRecord WHERE date = ?` 派生（需求里的"早跑晚骑算 2 次"天然成立），避免手工数字段与记录条数不一致。
- **卡路里**在保存时按 `kcal = MET × 体重kg × 时长小时` 计算并持久化（保留历史体重变更下的数值稳定性）。
- **未健身/已健身**状态由当日是否存在记录派生；日历格子颜色取该日记录的 `ExerciseType.color` 混合。

### 5.2 构建命令（PowerShell，注意本机 `&&` 不可用，用 `;`）

```powershell
# 会话内环境变量（JAVA_HOME 当前系统值失效，必须覆盖）
$env:JAVA_HOME   = "D:\insbuild\jdk17\jdk-17.0.20.1+1"
$env:ANDROID_HOME = "D:\insbuild\android-sdk"
$env:Path = "$env:JAVA_HOME\bin;$env:ANDROID_HOME\platform-tools;$env:Path"

cd "d:\桌面（2）\FitRecord\android"
.\gradlew.bat :app:assembleRelease          # 产物：app\build\outputs\apk\release\app-release.apk
# 真机安装（需先 USB 连接并授权）
& "$env:ANDROID_HOME\platform-tools\adb.exe" install -r "app\build\outputs\apk\release\app-release.apk"
```

`android/local.properties` 内容：`sdk.dir=D:/insbuild/android-sdk`（正斜杠，不入库）。

### 5.3 签名方案

```powershell
# 一次性生成（口令请自行留存，丢失将无法覆盖升级）
& "$env:JAVA_HOME\bin\keytool.exe" -genkeypair -v `
    -keystore fitrecord-release.keystore -alias fitrecord -keyalg RSA -keysize 2048 `
    -validity 10950   # 30 年
```
`keystore.properties`（storeFile / storePassword / keyAlias / keyPassword）在 `app/build.gradle.kts` 中读取；文件缺失时 release 构建回退到 debug 签名并打印警告，保证"任何机器都能出包"。
